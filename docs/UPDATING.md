# GitHub 自动更新

## 用户流程

从 v2.2.0 开始，启动工具后自动检查 GitHub 最新正式 Release。有新版时点击“下载并更新工具”，确认后下载并重启。重启后点击“安装 / 更新”将汉化应用到兼容的游戏客户端。

旧版 v2.1.0 没有检查更新代码，用户必须手动换到支持更新的版本一次。不能通过只修改仓库让已经下载的旧 EXE 获得更新能力。

检查更新和下载在后台运行。点击“取消下载”可以取消；关闭窗口时若仍在下载，会先请求取消，待完成后可关闭。单次网络读写超时为 15 秒，下载总时限约 5 分钟。网络错误、GitHub API 限流或缺少附件均可稍后重试，不影响本地安装和还原。

## 发布来源与校验

更新源固定为 `https://api.github.com/repos/lulinlulu888-design/Aion2-Steam-CN/releases/latest`，不需要用户登录或提供 GitHub Token。网页下载入口和 `docs/version.json` 不参与可执行文件下载，继续指向正式 Release 页面。

接受的 Release 必须：

- 是正式发布，非 draft、非 prerelease，并被 GitHub 选为 Latest。
- 标签为 `v主版本.次版本.修订版本`，且高于当前版本。
- 带有名称完全匹配的 `Aion2-Steam-CN-v版本号.exe` 附件，状态为 uploaded。
- 附件大小在 1 字节至 256 MiB 之间，GitHub API 提供有效的 `sha256:` digest。
- 下载地址属于本仓库该标签的 Release 附件。重定向只允许明确列出的 GitHub HTTPS 主机。
- 下载后大小、摘要、程序集版本和程序名称全部匹配。

SHA-256 用于完整性校验，**不是独立发布签名**。当前信任 GitHub 账户、仓库权限及系统 HTTPS 信任链；不抵御仓库发布权限被盗的情形。后续若加入独立签名，需要另外管理离线私钥和公钥轮换，不能把私钥提交进仓库。

## 替换与恢复

在工具所在目录创建唯一 `.aion2cn-update-*` 子目录。下载完成且校验通过后，把当前工具复制为更新助手。助手等待主进程退出，再次核验下载文件与旧文件，使用同卷 `File.Replace` 原子替换；不退化为直接覆盖复制。

更新成功后重新启动原路径，原文件保存在该子目录的 `previous.exe`。替换后校验失败或启动调用失败会恢复旧文件。若断电发生在替换后，旧文件仍在备份目录，可手动恢复；这不是跨断电的自动恢复事务。若新版本启动后才崩溃，目前没有健康检查或自动回退机制。

为保留恢复能力，成功更新后的目录暂不自动删除。工具目录不可写、磁盘空间不足或目标被其他进程占用时，更新会失败并提示，不强制关闭进程。更新助手不操作任何游戏文件。程序更新后仍使用现有游戏兼容性检查；本功能不代表自动适配新的游戏构建。

## 维护者发布步骤

1. 更新 `Aion2CNTool.cs` 中的程序集版本和 ToolVersion；语言变化时同步更新载荷版本、哈希和兼容构建。
2. 使用合法生成的载荷构建：`./build.ps1 -Payload '路径/L10NString.dat'`。默认生成 `bin/Aion2-Steam-CN.exe`，程序集名称保持不变。
3. 完成测试后，把 EXE 作为 `Aion2-Steam-CN-v版本号.exe` 上传到对应标签的 Release。文件重命名不改变程序集名称。
4. 先在草稿里上传附件，确认上传完整，再发布为 Latest 正式版本。不要先发布空 Release。
5. 核对 API 的附件 size、state、digest 和版本。缺少 digest 时工具会拒绝更新，不能绕过校验。
6. 同步 README、网站和版本清单。单独更新这些文档不会触发用户端更新；语言包改动也必须提升工具版本并发布完整 EXE。

## 验证

构建当前待发布版：

```powershell
./build.ps1 -Payload ./bin/L10NString.dat -Output ./bin/v2.2.0/Aion2-Steam-CN.exe
./tests/run-updater-tests.ps1
./tests/run-updater-tests.ps1 -Network
```

本地测试覆盖版本分支、发布类型、异常摘要和地址、文件损坏、已有备份保护、替换和启动失败回滚。`-Network` 额外从真实 GitHub Release 下载并校验附件、测试取消，不执行下载的 EXE、不修改游戏文件。测试临时目录路径会输出供检查。
